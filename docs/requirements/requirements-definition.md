## 1. プロジェクト概要

### 1.1 背景・目的

アウトソーシング事業部統括課では、パート従業員を中心とした従業員情報・雇用契約・勤務条件の管理を手作業（Excel・紙ベース）で行っている。特に雇用契約書の作成では、データベースに登録された情報を手作業で契約書に転記しており、転記ミスや作業時間の増大が課題となっている。

本プロジェクトでは、従業員データベースシステムを構築し、以下を実現する：

- 雇用契約書からの手入力作業を廃止し、DB情報からの自動入力によるPDF出力を実現
- 給与支払データ（CSV）作成の効率化と正確性向上
- 契約更新の見逃し防止（自動アラート機能）
- 同時編集制御によるデータ整合性の確保
- 監査ログによる変更履歴の追跡可能性の担保

### 1.2 スコープ

- **対象範囲**:
  - 従業員マスター管理（基本情報、勤務条件、給与情報、口座情報）
  - 雇用契約書の作成とPDF出力（契約書・誓約書）
  - 給与計算用データのCSV抽出
  - 給与システム連携（CSV専用エクスポートモード）
  - 契約更新アラート機能
  - 同時編集制御（EditLock）
  - 入退社を繰り返す従業員の管理（再雇用フロー）
  - 6ロール構成の権限制御
  - 監査ログ（7年間保持）
  - ダッシュボード（重要タスク表示・統計カード）

- **対象外**:
  - 給与計算処理そのもの（CSV出力までが範囲）
  - 勤怠管理システム
  - 給与システム側のインポート処理
  - モバイルアプリ（Expo）の本番運用（将来検討）

### 1.3 利害関係者

| 関係者 | 役割 | 関心事項 |
|--------|------|----------|
| 統括人事管理者 | 主要ユーザー（管理者・編集者（統括）） | 従業員情報の正確な管理、契約書作成の効率化、給与データの正確な抽出 |
| 現場マネージャー | 閲覧者 | 自部門の従業員情報閲覧、契約更新状況の把握 |
| 人事担当者 | 編集者（人事） | 従業員情報の入力・編集、CSV抽出、契約書PDF出力 |
| 監査担当者 | 監査ロール | 変更履歴の確認、コンプライアンスチェック |
| システム管理者 | システム管理者ロール | ユーザー管理、システム設定、全機能アクセス |

### 1.4 用語定義

| 用語 | 定義 |
|------|------|
| 社員コード | 従業員を一意に識別するコード。「部門コード+4桁番号」形式（例：BPS0001） |
| 枝番 | 契約書に自動付与される連番。再雇用時は退職前の最終枝番から継続採番 |
| 承認番号 | 契約書作成・再作成時に入力が必須となる管理番号 |
| 契約番号 | 「社員コード-CON+5桁番号」形式（例：BPS0001-CON00001） |
| 雇用満了予定日 | 契約の予定終了日。超過時に「要更新」表示の基準 |
| 雇用満了日 | 実際の雇用終了日（任意項目） |
| EditLock | 同時編集制御の仕組み。15分で自動解放 |
| フセン項目 | 従業員に付与する任意のメモ・タグ情報 |
| JSONB | PostgreSQLのJSON型カラム。複数の勤務時間帯等を配列形式で格納 |
| standby | 再雇用待機ステータス。退職後1年間有効、超過時にarchivedへ自動移行 |

## 2. 業務要件

### 2.1 現行業務フロー

1. 新規従業員の雇用情報をExcelの従業員台帳に手入力
2. 雇用契約書のテンプレート（Word/PDF）に従業員情報を手作業で転記
3. 契約書を印刷・押印し、従業員に交付
4. 給与計算時にExcel台帳から必要データを手作業でCSV形式に加工
5. 契約更新時期は担当者の記憶・Excelのフィルタリングで管理

### 2.2 目標業務フロー

1. 新規従業員の基本情報・社会保険情報をWebシステムに登録（勤務条件・契約は後から追加可能）
2. 契約管理ページから勤務条件・雇用契約を入力
3. 3点メニューから契約書PDFをプレビュー・ダウンロード・印刷（DB情報から自動入力）
4. 給与計算用データをCSV抽出画面から条件指定して一括出力
5. 契約更新アラートが30日前・14日前・7日前に自動通知
6. ダッシュボードで重要タスク・統計情報を一覧確認

### 2.3 業務内容

#### 手順

1. 統括人事管理者が従業員の基本情報と社会保険情報を登録する
2. 契約管理ページから勤務条件（勤務時間帯、休憩時間帯、勤務場所、交通費）と雇用契約（契約種別、契約期間、時給等）を入力する
3. 契約書・誓約書のPDFを生成し、プレビュー確認後に出力する
4. 契約更新時は3点メニューから「契約更新」を選択し、更新情報を入力する
5. 給与計算時にCSV抽出画面からプリセット選択・条件指定してデータを出力する
6. 退職・再雇用時はステータス遷移により同一レコードで管理する

#### 入出力情報

| 種別 | 情報名 | 形式 | 説明 |
|------|--------|------|------|
| 入力 | 従業員基本情報 | Webフォーム | 社員コード、氏名、生年月日、入社日、雇用区分、部門・所属コード等 |
| 入力 | 社会保険情報 | Webフォーム | 健康保険、厚生年金、雇用保険、労災保険の加入情報 |
| 入力 | 勤務条件 | Webフォーム | 勤務時間帯、休憩時間帯、勤務場所、交通費（JSONB配列） |
| 入力 | 雇用契約情報 | Webフォーム | 契約種別、契約期間、時給、残業時給、各種手当 |
| 入力 | 口座情報 | Webフォーム | 金融機関名・コード、支店名・コード、口座種別・番号・名義 |
| 出力 | 雇用契約書PDF | PDF | 契約書.pdfフォーマットでDB情報を自動入力 |
| 出力 | 誓約書PDF | PDF | 誓約書.pdfフォーマットで社員番号のみ自動入力 |
| 出力 | 給与計算用CSV | CSV | 時給、通勤費、社会保険フラグ、各種手当等17項目 |
| 出力 | 契約更新アラート | アプリ内通知 | 30日前・14日前・7日前に自動送信 |

### 4.2 機能詳細

#### F-001: 従業員情報登録・管理

- **入力**: 社員コード（部門コード+4桁番号）、氏名、氏名カナ、性別、生年月日、国籍、入社日、雇用区分、部門コード、所属コード（必須）、フセン項目（任意）、社会保険情報
- **処理**: 社員コードの一意性検証、基本情報と社保情報のDB保存。勤務条件が空の場合はwork_conditionsレコードを作成しない。契約番号・開始日が空の場合はcontractsレコードを作成しない。新規登録時はemployment_historyレコードを作成しない。
- **出力**: 従業員一覧画面に新規従業員が表示される。情報未完了の場合はダッシュボードに「情報未完了」バッジを表示。
- **制約**: 社員コードの重複時はインラインエラー表示。Enterキー押下時は保存せず次フィールドへ移動。
- **完了条件**: 基本情報＋社保情報のみで登録完了し、勤務条件・契約を後から追加できること

#### F-002: 勤務条件管理

- **入力**: 勤務時間帯（複数）、休憩時間帯（複数）、勤務場所（複数）、交通費情報（ルート別：往復金額、月額定期、上限金額、最寄り駅）、勤務日数タイプ、勤務日数、有休基準日
- **処理**: 各データをJSONBカラム（working_hours_jsonb、break_hours_jsonb、work_locations_jsonb、transportation_routes_jsonb）に配列形式で保存。勤務時間帯の重複バリデーション、休憩時間帯の勤務時間内チェック。
- **出力**: 勤務条件が従業員詳細・契約画面に表示される
- **制約**: 契約管理コンテキストでは勤務時間帯・勤務場所が各1つ以上必須。従業員登録コンテキストでは未入力を許容。
- **完了条件**: 複数の勤務時間帯・場所を正しく保存・表示できること

#### F-003: 雇用契約書PDF出力

- **入力**: 契約書出力対象の従業員・契約情報
- **処理**: 契約書.pdfフォーマットでDB情報（契約者氏名、作成年月日、雇用期間、就業場所、業務内容、勤務日、社保加入、休暇、賃金）を自動入力。誓約書は社員番号のみ自動入力。枝番を自動付与。
- **出力**: 契約書PDF、誓約書PDF。プレビューポップアップでダウンロード・印刷が可能。
- **制約**: 承認番号の入力が必須。勤務条件・契約情報が全項目入力済みの場合のみ出力許可。未完了時はエラーメッセージと不足項目を表示。契約書再作成時は既存契約書を無効化。
- **完了条件**: PDF出力にすべての必要項目が自動入力されていること

#### F-004: 給与計算用CSV抽出

- **入力**: 抽出条件（対象従業員、指定日時点、出力項目選択）
- **処理**: 指定時点で有効な情報のみを抽出。口座情報を選択的に含めることが可能。情報未完了の従業員も抽出対象（未入力項目は空欄出力）。
- **出力**: CSV形式ファイル（時給、残業時給、通勤費、社保フラグ、各種手当等17項目）
- **制約**: 管理者・編集者（統括）・編集者（人事）のみ実行可能。口座情報含むCSV出力時は監査ログに「口座情報含む」フラグを記録。
- **完了条件**: 100人分の給与CSVを30秒以内に抽出できること

#### F-005: 契約管理画面操作メニュー

- **入力**: 3点メニュークリック操作、チェックボックスによる複数選択
- **処理**: 「契約書プレビュー」「誓約書プレビュー」「契約更新」「新規契約作成」「契約削除」の5操作を提供。一括ダウンロード・印刷機能を提供。
- **出力**: メニュー表示、プレビューポップアップ、各画面への遷移
- **制約**: 契約更新・新規作成は従業員管理ページに遷移しない（独立画面）。チェック未選択時は一括ボタンを無効化。削除は確認ダイアログを表示。
- **完了条件**: 5つのメニュー操作がすべて正常動作すること

#### F-006: 契約作成・更新画面

- **入力**: 契約番号、承認番号、contracts情報（契約種別、契約開始日、雇用満了予定日、時給、残業時給等）、work_conditions情報（勤務時間帯、休憩時間帯、勤務場所、交通費等）
- **処理**: 従業員基本情報はDBから取得してウィジェット外に固定表示。勤務条件と雇用契約のみ入力可能。新規契約作成ページでは書類・提出状況と社会保険・給与情報も入力可能。
- **出力**: 入力情報のDB保存
- **制約**: 基本情報は編集不可。契約番号と承認番号の入力欄を画面先頭に配置。
- **完了条件**: contracts・work_conditionsテーブルの情報を正しく保存・表示できること

#### F-007: 編集権限制御（画面分離）

- **入力**: 従業員管理ページからの画面遷移
- **処理**: 従業員管理ページの「編集」「新規登録」画面では基本情報のみ表示。勤務条件・雇用契約のウィジェットを非表示。
- **出力**: 基本情報のみの編集画面
- **制約**: 契約情報の編集は契約管理ページからのみ可能。
- **完了条件**: 従業員編集画面に勤務条件・雇用契約が表示されないこと

#### F-008: 契約履歴自動記録

- **入力**: 契約の作成・更新操作
- **処理**: employment_historyテーブルに契約番号・承認番号とともに、work_condition_snapshot（JSONB）、contract_terms_snapshot（JSONB）、documents_snapshot（JSONB）を自動保存。
- **出力**: 契約履歴タブに時系列で表示（契約番号の下に承認番号を表示）
- **制約**: 手動記録は不可（自動追記のみ）。
- **完了条件**: 契約作成・更新時にemployment_historyに正しくスナップショットが記録されること

#### F-009: 契約情報の表示制御

- **入力**: 従業員管理画面の表示リクエスト
- **処理**: contract_start_dateが未来の場合は現行契約を表示。当日または過去の場合は新契約を表示。複数契約がある場合は最新の有効契約を表示。
- **出力**: 勤務情報、給与・手当、書類、備考の各タブに適切な契約情報を表示
- **制約**: 有効な契約が存在しない場合は「契約情報なし」を表示。
- **完了条件**: 契約開始日を基準に正しく表示が切り替わること

#### F-010: 契約満了「要更新」表示

- **入力**: 契約一覧・従業員一覧・従業員詳細の画面表示
- **処理**: employment_expiry_scheduled_dateが当日の日付を過ぎている契約に「要更新」を赤色で表示。当日は対象外（翌日から表示）。NULLの場合は表示しない。
- **出力**: 赤色の「要更新」バッジ
- **制約**: 契約管理画面、従業員管理ページ、従業員詳細ページの3箇所で表示。
- **完了条件**: 満了予定日超過時に正しく「要更新」が表示されること

#### F-011: 権限モデル（6ロール）

- **入力**: ユーザーのロール情報
- **処理**: 6ロール（system_admin, admin, editor_supervisor, editor_hr, viewer, auditor）に基づく権限制御。サーバー側で操作ごとに権限を再検証。
- **出力**: ロールに応じた機能アクセス制御

| 機能 | system_admin | admin | editor_supervisor | editor_hr | viewer | auditor |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| 従業員閲覧 | o | o | o | o | o（自部門のみ） | o |
| 従業員編集 | o | o | o | o | x | x |
| 契約書PDF出力 | o | o | o | o | x | x |
| CSV抽出 | o | o | o | o | x | x |
| 口座情報アクセス | o | o | o | x | x | x |
| 承認処理 | o | o | o | x | x | x |
| ユーザー管理 | o | o | x | x | x | x |
| 監査ログ閲覧 | o | o | o | x | x | o |
| システム設定 | o | x | x | x | x | x |

- **制約**: 個人番号・給与情報へのアクセスは管理者・編集者（統括）のみ。閲覧者は自部門データのみアクセス可能。
- **完了条件**: 各ロールの権限マトリクスが100%正しく動作すること

#### F-012: 口座情報管理

- **入力**: 金融機関名（VARCHAR(100)）、金融機関コード（VARCHAR(4)）、支店名（VARCHAR(100)）、支店コード（VARCHAR(3)）、口座種別（普通/当座）、口座番号（VARCHAR(7)）、口座名義（VARCHAR(100)、カナ）
- **処理**: Supabase Vault（pgsodiumエクステンション）によるDBレベルAES-256暗号化。アプリケーションレイヤーでの暗号化ロジックは不要。口座情報へのアクセスはすべて監査ログに記録。
- **出力**: 従業員詳細画面の口座情報セクション
- **制約**: 管理者・編集者（統括）のみがアクセス可能。退職時に口座情報をマスク、再雇用時は再入力を要求。口座番号は7桁数字、金融機関コードは4桁。
- **完了条件**: 暗号化保存・権限制御・監査ログが正しく動作すること

#### F-013: 入退社繰り返し管理

- **入力**: ステータス変更操作、再雇用ボタンクリック
- **処理**: ステータス遷移（active→retired→standby→active/archived）。再雇用時は基本情報・社保情報を引継ぎ、勤務条件・契約・口座情報は新規入力を要求。standby期間は退職後1年間、超過時にバッチ処理でarchivedへ自動移行。
- **出力**: ステータス変更結果、再雇用処理画面
- **制約**: 同一社員番号を再利用。枝番は退職前の最終枝番から継続採番。archivedステータスからの再雇用は不可。
- **完了条件**: 再雇用処理が10分以内に完了できること

#### F-014: 給与システム連携CSV

- **入力**: プリセット選択、差分出力オプション、出力項目選択
- **処理**: Phase 1ではシステム固定プリセット（汎用CSVフォーマット）。カラム順・項目選択のみカスタマイズ可能。差分出力は前回エクスポート日時との比較。プレビュー（先頭10行）提供。
- **出力**: 給与システムインポート仕様準拠のCSVファイル（17項目：社員番号〜口座名義）
- **制約**: Phase 2でDB管理のカスタムプリセット機能を追加予定。エクスポート履歴（日時・件数・実行者）を記録。
- **完了条件**: 仕様に100%準拠したCSVが出力され、差分出力が正しく動作すること

#### F-015: CSVインポート検証記録

- **入力**: export_id、import_result（success/partial/failed）、error_details（任意）、error_count、success_count
- **処理**: EXPORT_VERIFICATIONテーブルにINSERT。export_idはエクスポート履歴に存在する値であること。
- **出力**: エクスポート履歴画面に検証結果ステータスを表示
- **制約**: 管理者・編集者（統括）・編集者（人事）のみ登録可能。
- **完了条件**: 検証結果が正しく記録・表示されること

#### F-016: 契約更新アラート

- **入力**: 契約の雇用満了予定日
- **処理**: 30日前・14日前・7日前にアプリ内通知を自動送信。契約書が出力された場合はアラートを自動解除。
- **出力**: アプリ内通知
- **制約**: 通知対象は統括人事管理者と現場マネージャー。
- **完了条件**: アラートが100%の精度で送信されること

#### F-017: 同時編集制御

- **入力**: レコード編集リクエスト
- **処理**: EditLockテーブルで排他制御。対象リソース（EMPLOYEE/CONTRACT/WORK_CONDITION）ごとにロック管理。15分で自動解放。
- **出力**: 編集不可メッセージ（ロック中の場合）、最終更新日時・更新者の表示
- **制約**: すべての編集画面に最終更新日時と更新者を表示。
- **完了条件**: 同時編集の競合が100%防止されること

#### F-018: ダッシュボード

- **入力**: ダッシュボード画面表示リクエスト
- **処理**: 「要更新」ステータスのタスクを赤色表示。優先度を契約残日数で設定（60日未満：高、60〜90日：中、90日以上：低）。統計カード3種の集計。
- **出力**: 重要タスク一覧、統計カード（従業員数、今月の契約処理、契約更新予定（30日以内））
- **制約**: 情報未完了の従業員には「情報未完了」バッジを表示。
- **完了条件**: タスクの色分け・優先度・統計カードが正しく表示されること

#### F-019: 監査ログ

- **入力**: 全変更操作（自動記録）
- **処理**: action、resource_type、resource_id、old_values（JSONB）、new_values（JSONB）、ip_address、user_agentを記録。
- **出力**: 監査ログ閲覧画面
- **制約**: 7年間保持。口座情報アクセス時は閲覧・編集いずれも記録。
- **完了条件**: すべての変更操作が100%監査ログに記録されること

#### F-020: バリデーションコンテキスト

- **入力**: コンテキスト識別子（employee-management / contract-management / all）
- **処理**: employee-managementコンテキストでは勤務条件・契約情報のバリデーションを緩和（空配列・ゼロ値を許容）。contract-managementコンテキストでは勤務時間帯・勤務場所を必須。フセン項目は全コンテキストで任意。workDaysCountはemployee-managementコンテキストで0を許容。
- **出力**: コンテキストに応じたバリデーション結果
- **制約**: PDF出力（法的文書）は全項目必須。CSV抽出は情報未完了でも可能（空欄出力）。
- **完了条件**: 画面ごとに正しくバリデーションが切り替わること
