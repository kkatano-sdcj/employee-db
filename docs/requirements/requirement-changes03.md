# 要件定義の変更点

以下に要件定義の変更点を記載する

変更点: 画面表示とページ遷移の変更

## 契約管理ページ
契約管理ページから各従業員の契約情報を修正する際のページ表示を編集する。変更内容を以下に示す。

**変更内容**
- 「契約更新」と「新規契約作成」のページはそれぞれ独立して設定する。
- 「契約更新」と「新規契約作成」のページの入力項目は`勤務条件` と `雇用契約`のみを入力欄とし、従業員の基本情報はデータベースから取得し、ウィジェットの外に固定表示する。
- 従業員の情報を「操作」のポップアップメニューから開く場合は、従業員管理ページには遷移しない。
- 従業員を選択して新規契約を作成する場合は、従業員の基本情報は固定表示する。
- 新規契約作成ページで入力する項目は、`勤務条件`、`雇用契約`と`書類・提出状況`、`社会保険・給与情報`のみとする。
- 新規契約作成、契約更新ページにも`承認番号`の入力欄を設ける。


## 従業員管理ページ

従業員管理ページの表示を以下のように修正する、

**変更内容**
- 契約履歴タブの `契約番号` の下に、`承認番号` を表示する。
- supabaseの　`employment-history` テーブルに、承認番号（approval-number）を登録・保存できるようにします。
- 新規の従業員登録ページと従業員情報を編集ページでは、`勤務条件`と`雇用契約`ウィジェットは表示しないようにする。


## 契約番号の命名規則

以下の契約番号の命名規則を示す。

- 従業員番号-契約識別番号
 例）
 BPS0001-CON00001
 BPS0001-CON00002
 BPS0002-CON00001
 CC0001-CON0001
 PS0001-CON0001
 PS0002-CON0001
 PS0001-CON0002

- 従業員の識別番号はコード + ４桁の番号
- 契約番号はCON + ４桁の番号
- 従業員のコードは部門選択で自動的に振られ、番号は同じ部門コード内の連番とする
- 契約識別番号の数字は、同じ従業員の持つ番号の連番とする

### 部門名と部門コード
- BPS課: BPS
- オンサイト課: ONS
- CC課: CC
- PS課: PS
